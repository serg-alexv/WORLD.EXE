# Operating boundaries

## Independent lanes

1. **Source recovery:** existing native Windows five-minute WORLD.EXE source snapshots. Extend the allowlist and registered worktree for Gamebox source only. Never include runtime state, tokens, imports, captures, model weights or personal feedback. Snapshots are recovery copies, not AI development and not accepted builds.
2. **Validation:** event-driven Gamebox CI runs portable tests, source-backup boundary tests, a synthetic demo and a labeled microbenchmark. No signing credentials, deployment, app submission, provider calls or real user fixtures. One concurrency group per branch cancels superseded validation, not a completed release.
3. **First outside review:** the existing hourly automation remains read-only for Apple and repositories and pinned to Fusion 0.4.0 (8.1), build e4e8f63b-4341-4657-b586-bc35d43d6400. Read current private receipts first. A qualifying comment still requires independent semantic assessment. Do not manufacture, solicit through impersonation, or publish private feedback.
4. **Platform checkpoint:** a separate scheduled technical check may assess changed source/test receipts, safety gates and operational drift. It must not duplicate first-player notifications or perform autonomous deployments. Its authoritative prompt is stored with the task and private project receipt, not hidden in public feedback.

The installed task inventory and exact changes are recorded in private `WORLD.EXE-ops/GAMEBOX_LATEST.md` and `gamebox-platform-current.json`. Source `config/schedules.json` is a declarative contract, not evidence that an OS/cloud scheduler has been installed. GitHub workflow schedules are not manufactured merely by writing this file.

## Promotion and secrets

Current release remains unchanged. Promote a future candidate only after review and the relevant native/physical/online gates. No auto-merge or release dispatch is installed here. Never widen Apple API permissions or bypass Windows Security PIN/MFA. No access tokens or authentication material are read into public receipts. Existing protected Apple authentication is consumed by the established read-only watcher without extracting its secret values.

Monitor notifications are transition-based and deduplicated using build/submission/feedback IDs. An API outage or pagination limit is a blind spot, never zero feedback. Anonymous written feedback can be an attribution blocker, not completion. A negative or brief genuine opinion can qualify. Upon a verified first review, preserve only the necessary private assessment and disable that watcher, not source recovery or platform checks.

## Recovery and solo-operator limits

Pause before local experiments that change configuration. Drain to stop admissions while existing sessions finish. Save source changes in the isolated branch, not the released main checkout. Keep state outside Git. Repeated control IDs are idempotent for the retained 128-command window; stale revision checks remain mandatory. Match state is ephemeral and a process restart disconnects sessions.

Before public scale, add independent disaster-recovery evidence, abuse/moderation response, regional failover, managed identity, secrets rotation, cost accounting and someone who can respond when the sole operator cannot. Automation can reduce routine work; it does not demonstrate that one person can support millions continuously.
